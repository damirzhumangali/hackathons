# CQA Backend

FastAPI и SQLite для импорта диалогов, оценки по версиям чек-листа и пересмотра результатов. Локальный интерфейс доступен на `/`, спецификация API — на `/docs`.

## Локальный запуск

Нужен Python 3.11 или новее. Выполните из корня проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000`. При старте создаются `data/cqa.sqlite3` и версия v1 стартового чек-листа. Команда `python -m app.db` выполняет ту же инициализацию отдельно. `curl -i http://127.0.0.1:8000/health` должен вернуть HTTP 200.

Для импорта DEV задайте `CQA_DATASET_URL` в окружении сервера перед запуском Uvicorn. Используйте полный адрес кнопки **«Открыть GET для DEV»** со страницы 3 задания. Сервер подставляет запрошенный `group_id` и сохраняет остальные параметры исходной ссылки. В интерфейсе укажите `DEV` и нажмите **«Импортировать из API»**. То же действие через терминал:

```sh
curl -fsS http://127.0.0.1:8000/api/imports \
  -H 'Content-Type: application/json' \
  -d '{"group_id":"DEV","source":"organizers"}'
```

Для загрузки синтетических примеров укажите группу `DEMO` и выберите `tests/fixtures/dialogues.json` в интерфейсе. Можно загрузить тот же файл напрямую:

```sh
curl -fsS http://127.0.0.1:8000/api/imports \
  -H 'Content-Type: application/json' \
  --data-binary @tests/fixtures/dialogues.json
```

## Процесс оценки

В отдельном терминале откройте корень проекта, активируйте `.venv`, задайте переменные окружения для своего провайдера и запустите `python -m app.worker`. Процесс забирает задания из SQLite. При выборе нестандартного файла базы укажите одинаковый `CQA_DB_PATH` для сервера и обработчика.

| Переменная | Где нужна | Значение |
|---|---|---|
| `CQA_DB_PATH` | Сервер и обработчик | Путь к SQLite. По умолчанию `data/cqa.sqlite3` внутри проекта. |
| `CQA_DATASET_URL` | Сервер | Полный адрес API организаторов для импорта по `group_id`. |
| `CQA_LLM_URL` | Обработчик | Полный URL OpenAI-совместимого `chat/completions`. |
| `CQA_LLM_MODEL` | Обработчик | Название модели у выбранного провайдера. |
| `CQA_LLM_API_KEY` | Обработчик | Ключ, если его требует провайдер. |
| `CQA_LLM_TIMEOUT` | Обработчик | Таймаут запроса в секундах, по умолчанию `60`. |
| `CQA_LLM_RESPONSE_FORMAT` | Обработчик | `json_object` по умолчанию. Для Ollama можно выбрать `json_schema`, чтобы ограничить формат ответа и ID доказательств. |

### Локальный Qwen3 через Ollama

Из корня проекта запустите Ollama в отдельном терминале. Для локальной копии CLI подойдёт следующая команда. Если CLI установлен в `PATH`, замените `data/ollama/runtime/ollama` на `ollama`.

```sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_MODELS="$PWD/data/ollama/models" \
  OLLAMA_NO_CLOUD=1 OLLAMA_CONTEXT_LENGTH=8192 OLLAMA_NUM_PARALLEL=1 \
  data/ollama/runtime/ollama serve
```

Один раз скачайте модель в работающий Ollama и запустите обработчик CQA в другом терминале:

```sh
data/ollama/runtime/ollama pull qwen3:4b-instruct-2507-q4_K_M
CQA_LLM_URL=http://127.0.0.1:11434/v1/chat/completions \
  CQA_LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M \
  CQA_LLM_RESPONSE_FORMAT=json_schema CQA_LLM_TIMEOUT=180 \
  .venv/bin/python -m app.worker
```

Ollama в этой конфигурации принимает запросы только с этого компьютера. Ключ API не нужен. Для звонков оценивается сохранённый транскрипт.

Выберите диалог и версию чек-листа в интерфейсе. Кнопка **«Открыть транскрипт»** позволяет просмотреть диалог и его прежние версии до оценки. Кнопка **«Оценить группу»** обрабатывает активные версии диалогов указанной группы. Повторный импорт прежней версии снова делает её активной без дубликата. Ссылка в адресной строке сохраняет открытый прогон, и за ним можно продолжить следить после обновления страницы.

В карточке результата нажмите ссылку на доказательство, чтобы перейти к реплике. Там же можно подать апелляцию и принять решение. Редактор сохраняет новую версию правил, которую можно выбрать для следующей оценки.

Для оценки на синтетических примерах сравните вывод модели с наблюдениями:

| Диалог | Что проверить вручную |
|---|---|
| `demo-ru-public` | Общий вопрос о тарифах не требует идентификации. Оператор предложил дальнейшую помощь, но не попрощался. |
| `demo-kz-protected` | Оператор сообщил баланс без подтверждённой идентификации. Для критерия 03 ожидается «Нет», а раскрытие информации отмечается отдельно. |
| `demo-en-call` | В транскрипте есть приветствие, имя, реакция на неудобство, следующий шаг и прощание. Метки времени звонка сохраняются с часовым поясом. |

Локальные тесты проверяют расчёт баллов, валидацию ответов модели, обработку очереди и пересмотр без ключа провайдера:

```sh
python -m unittest discover -s tests -v
```
